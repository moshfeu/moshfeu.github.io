# AGENTS.md

This repository contains my personal blog and technical writing. It is small, opinionated, and mostly focused on practical engineering notes, terminal workflows, and developer tooling.

## Purpose

Keep the repository useful for writing and publishing concise technical posts without adding unnecessary ceremony. The content should read like a personal engineering notebook: direct, useful, and grounded in real workflows.

## Writing style

Follow the tone used in existing posts:

- straightforward and technical, but accessible
- direct and concise
- minimal personality, no hype or clickbait
- present tense, practical explanations
- prefer examples that solve a real problem over broad theory

Avoid:

- exaggerated marketing language
- “here’s a neat trick” framing
- rhetorical questions in headings
- overuse of “you” or direct reader addressing
- dramatic or overly casual phrasing

## Post structure

All posts should use this structure when appropriate:

1. Background or context
2. The Problem
3. The Solution
4. Additional sections only if useful

Frontmatter is required and should look like:

```yaml
---
title: Clear, descriptive title
tags: ["relevant", "tags", "3-5 tags"]
slug: kebab-case-url-slug
date: YYYY-MM-DD
---
```

## Code examples

- Prefer complete, working snippets
- Explain what the code does in plain language after the example
- Keep examples focused and minimal
- Use fenced code blocks with an appropriate language tag

## Content expectations

- Write as if publishing to a personal developer blog
- Emphasize real-world problems and concrete fixes
- Keep articles practical, not tutorial-heavy for the sake of length
- Favor code and examples over long conceptual explanations

## Operational guidance

When adding or editing content:

- keep the repository clean and consistent
- preserve the established MDX blog format
- use clear file names and slug values that match the post title
- keep tags specific and useful
- prefer small, focused posts over broad “everything” articles

## Specific project context

This blog is a personal site for publishing notes about:

- terminal workflows
- shell configuration and productivity
- Git and software development habits
- IDE and tooling ergonomics
- practical frontend, web tooling, and engineering problem solving

The writing should feel like a useful note from a developer who is solving real problems while working day to day.
